Reading this record

What a CxBOM is

A Context Bill of Materials records what went into a model's context window, the way a software bill of materials records what went into a build. It extends CycloneDX 1.6. Each entry names a component, its source and provenance, its trust ring, and its token share. The record is a description of one assembled context: it states what was assembled and which controls were or were not applied. It does not run the model or change how the model behaves.

What the trust rings mean

Every component carries a trust ring, assigned before the model runs, that records where the content came from:

  • Ring 0, operator — content the operator authored, such as the system prompt.
  • Ring 1, agent — content the agent brought in, such as tool definitions and retrieved documents.
  • Ring 2, user — input from the person using the agent.

A ring is a label, not a privilege. Token Democracy means the model gives every token the same computational weight whatever its ring: the ring organizes the record, it does not change the computation. Lower-ring content is not down-weighted by the model because of its ring.

The tool-definition inversion

When an agent loads a tool definition from an external server, that definition can be placed into the context with the same position and formatting as the operator's own instructions, and with no boundary marking it as lower trust. Its provenance is Ring 1, because it came from outside the operator, yet its position in the context carries operator-level authority.

CxBOM calls this a tool-definition trust inversion and records it as a finding, naming the component, the authority its source claims, and the authority its position gives it. The record flags the mismatch so a reviewer can see it. It does not block the tool, verify the server, or stop any particular attack; those are separate controls.

How to read the panels
  • The trust-ring diagram draws the three rings as concentric bands, operator core inward to user outward, with every component an arc on its ring. The bands are equal thickness so each ring stays legible whatever its token share; each arc's angle is its share within its own ring, floored so a tiny component is still visible. Hover an arc, or use the buttons beneath the diagram, for each component's detail. The connector reaching into the core marks the tool-definition trust inversion.
  • The component inventory lists the same components as rows: type, ring, token count, share, and any injection-risk flag the record carries.
  • The findings describe each recorded issue with its severity and the catalog entries it maps to (OWASP LLM, OWASP Agentic, CWE).
  • Control-layer coverage shows which control layers the record marks active, partial, or inactive.

Token share describes what was assembled before inference, not how the model used it.
